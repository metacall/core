## Reporting Issues & Requesting Features

If you encounter a bug or have a feature request, please open an issue in our repository.

### Issue Templates Guide
To help us diagnose and resolve issues efficiently, please follow these guidelines:
* **Bug Reports:** Use the bug report template if available. Provide a clear description, minimal reproducible code sample, operating system, and MetaCall version.
* **Feature Requests:** Detail the use case, expected behavior, and potential architecture or API impact.
* **Questions:** General "how-to" questions should ideally be asked in Discord or GitHub Discussions rather than as bug reports.

---

## Review & Response SLA

MetaCall is actively maintained by core maintainers and community contributors. We strive to adhere to the following response timeline:

* **Triage & First Response:** We aim to review and respond to newly opened issues and Pull Requests within **3 to 5 business days**.
* **Bug Fixes & Security Reports:** Critical regressions and security issues take top priority. Security concerns should be sent directly to `contact@metacall.io`.
* **Pull Request Reviews:** PRs are reviewed iteratively. Please ensure all automated checks pass to avoid delays in merging.
